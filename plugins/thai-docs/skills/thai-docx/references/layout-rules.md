# หลักจัดหน้า Word ภาษาไทย และสูตรที่ใช้ได้ผล

ถอดจากงานจริง: รายงานวิจัยฉบับเต็ม (~120 หน้า), ต้นฉบับส่งเผยแพร่, แบบแสดงรายละเอียดขอประเมินผลงาน/ประเมินบุคคล
และแบบเสนอแนวคิดการพัฒนา ข้อที่ระบุ "→ `fix`" คือคำสั่ง `python "<โฟลเดอร์ skill>/scripts/thaidocx.py" fix IN OUT` ทำให้แล้ว

## 1. หลักการ 10 ข้อ

1. **ทุก run ที่มีอักษรไทย (รวมเลขไทย ๐–๙) ต้องมี `<w:cs/>` และ `<w:lang w:val="en-US" w:bidi="th-TH"/>`**
   ไม่งั้น Word ถือเป็นภาษาอังกฤษ: ขึ้นเส้นหยักแดง ตัดคำผิด และกระจายช่องไฟยืด → `fix`
   (ยกเว้นไฟล์ที่ `wrap` แล้ว ซึ่งตั้งใจไม่ติดป้ายไทย ดู `wrap-words.md`)
2. **ฟอนต์เดียวทั้งเอกสาร** ตั้ง `rFonts` ครบ `ascii` `hAnsi` `cs` เป็น TH Sarabun New และลบ
   `asciiTheme/hAnsiTheme/cstheme` (theme ชนะค่าที่ตั้งตรง) รวมทั้ง docDefaults ใน styles.xml และ numbering.xml
   ยกเว้นฟอนต์สัญลักษณ์ของ bullet (Symbol, Wingdings, Courier New) → `fix` (เปลี่ยนฟอนต์ด้วย `--font`)
3. **`sz` ต้องเท่ากับ `szCs`** ไทยใช้ szCs อังกฤษใช้ sz ถ้าไม่เท่า คำอังกฤษ เช่น (SAR), Proctor
   จะตัวเล็ก/ใหญ่กว่าไทยรอบข้าง ตัวหนาต้องมีทั้ง `b` และ `bCs` → `fix`
4. **ย่อหน้าเนื้อความใช้ `jc=thaiDistribute`** (กระจายแบบไทย) ยกเว้นหัวเรื่องกึ่งกลาง สารบัญ คำบรรยายภาพ
   และรายการอ้างอิง (ชิดซ้าย เพราะมี URL/DOI) → `fix --distribute` (ข้ามหัวข้อ สารบัญ คำบรรยายภาพ
   ย่อหน้าที่จัดกึ่งกลาง/ขวาไว้แล้ว และย่อหน้าที่มี URL) **ไม่ข้าม** รายการอ้างอิง/บรรณานุกรมที่ไม่มี URL
   และบรรทัดสั้น (ชื่อ ที่อยู่ ข้อความบรรทัดเดียว) ตรวจด้วยตาแล้วตั้งกลับเป็นชิดซ้ายถ้าจำเป็น
5. **ห้ามขึ้นบรรทัดด้วยมือ (Shift+Enter / `<w:br/>`) เพื่อจัดคำไทย** เมื่อฟอนต์หรือขอบเปลี่ยน บรรทัดจะแตก
   กลางประโยค → `fix --remove-manual-breaks` (เก็บ break ที่คั่นรายการ "- …", "– …", "• …")
6. **ห้ามเคาะช่องว่างแทนการเยื้อง/จัดตำแหน่ง** ใช้ first-line indent 1.25 ซม. (720 twip ในแบบฟอร์มส่วนใหญ่)
   ช่องลงชื่อใช้ left indent + จัดกึ่งกลาง (ข้อ 3 ของสูตรด้านล่าง)
7. **เรียงลำดับ element ใน `rPr` / `pPr` / `tblPr` ตาม schema** ทุกครั้งที่เพิ่ม element
   (มิฉะนั้น Word แจ้งซ่อมไฟล์) → `fix` และ `layout.finalize` เรียงให้แล้ว ถ้าแก้ XML เองต้องเรียงเอง
8. **ซ่อนเส้นตรวจคำ** ใส่ `hideSpellingErrors` + `hideGrammaticalErrors` ใน settings.xml → `fix`
9. **หัวข้อต้องติดกับเนื้อหาถัดไป** (`keepNext`) กันหัวข้อค้างท้ายหน้า → `fix` (สไตล์ Heading/หัวเรื่อง,
   outlineLvl หรือข้อความขึ้นต้น "ส่วนที่", "บทที่", "ตารางที่", เลขหลายระดับ เช่น "1.1")
   ช่องลงชื่อทั้งชุดตั้ง `keepNext`+`keepLines` เอง ไม่ให้แยกหน้า
10. **ห้ามแก้ทับไฟล์ผู้ใช้ และห้ามลบ/ปลอม metadata, rsid หรือเวลาแก้ไข** บันทึกเป็นเวอร์ชันใหม่ (v1 → v2) เสมอ
    คำสั่งทุกตัวปฏิเสธถ้าไฟล์ปลายทางเป็นไฟล์เดียวกับต้นทาง หรือพบไฟล์ล็อก `~$` (ไฟล์เปิดอยู่ใน Word)

ลำดับ post-process (ทำใน `fix` แล้ว): แก้อักษรเพี้ยน → ฟอนต์ → sz=szCs → ลบ br มือ → เลขไทย → thaiDistribute →
keepNext หัวข้อ → ระยะบรรทัดเดี่ยว (single_spacing) → ระยะก่อนย่อหน้า (`--doc`) → ค่าเริ่มต้นเอกสาร → ป้ายภาษาไทย + ซ่อนเส้นตรวจคำ (หลังสุด เพราะขั้นอื่นสร้าง run ใหม่) →
(เลือก) ตัดคำ หลังแก้เนื้อหาทุกครั้งต้องรัน `fix` (หรือ `layout.finalize`) ใหม่ โดยใส่ตัวเลือกเดิมซ้ำทุกครั้ง
(`--thai-digits`, `--distribute`, `--remove-manual-breaks`, `--font`, `--wrap-words` …) ไม่งั้นขั้นนั้นจะไม่ถูกทำกับเนื้อหาใหม่

## 2. เลขไทยหรือเลขอารบิก

| เอกสาร | ใช้ |
|---|---|
| แบบฟอร์ม ก.พ./ประเมินบุคคล/ประเมินผลงาน, หนังสือราชการ, แบบเสนอแนวคิด | **เลขไทยทั้งเล่ม** (ถามผู้ใช้ก่อน) → `fix --thai-digits` |
| ต้นฉบับบทความ/รายงานส่งวารสาร (ค่าสถิติ ปี ค.ศ. DOI การอ้างอิง Vancouver/APA) | **คงเลขอารบิก** (ค่าเริ่มต้น) |

สิ่งที่ `--thai-digits` ทำ:

- แปลงเฉพาะข้อความใน `w:t` ไม่แตะ `w:instrText` (เช่น `TOC \o "1-3"` ถ้าแปลงสารบัญจะพัง)
- คงเลขอารบิกอัตโนมัติ: URL (`http…`, `www.…`), อีเมล, DOI (`doi:…`, `10.xxxx/…`),
  รหัสที่ขึ้นต้นด้วยอักษรละติน (`COVID-19`, `v2.0`, `HC3`), `ISO 27001`, `ISO/IEC 27001:2022`, `ICC(1)`
- ตัวเลขล้วน เช่น เบอร์โทรศัพท์ `038-123456` จะเป็นเลขไทย ส่วนรหัสที่ขึ้นต้นด้วยอักษรละตินคงเลขอารบิก
- แปลงทีละย่อหน้าโดยต่อข้อความทุก run ก่อน (ตัวเลขบางทีแยกหลาย run) แล้วคืนตามความยาวเดิม
- เลขข้ออัตโนมัติ: `numFmt decimal` → `thaiNumbers` ใน numbering.xml
- เลขหน้า: `pgNumType w:fmt="thaiNumbers"` ในทุก `sectPr`
- ติดป้ายไทยให้ run ที่เดิมมีแต่ตัวเลข (เพราะตอนนี้เป็นอักษรไทยแล้ว)

ตรวจผล: `check ไฟล์.docx --thai-digits` จะรายงาน `ARABIC_DIGITS` ถ้ายังเหลือเลขอารบิก (ไม่นับที่คงไว้ตามกติกา)

## 3. สูตรจัดหน้าแบบฟอร์มราชการ (ค่าที่ใช้ได้ผล)

- เนื้อความ 16 pt, ข้อความในตาราง 14 pt, หมายเหตุใต้ตาราง 12 pt, ระยะบรรทัด single (`line=240`, `after=0`) ในตาราง
- ย่อหน้า first-line 720 twip, หัวข้อระดับ 1 `spacing before=120`, หัวข้อย่อย `before=60` (แต่ `fix --doc รายงาน` ตั้ง 6 pt = 120 ให้หัวข้อทุกระดับ)
- ระยะบรรทัด: `fix` บังคับ single เสมอ (`line=240 lineRule=auto`, `after=0`) ที่ docDefaults สไตล์ และทุกย่อหน้า
  (ทุกส่วนรวมตาราง หัว/ท้ายกระดาษ เชิงอรรถ) ยกเว้นระยะแบบ exact ที่ตั้งใจล็อกความสูงไว้ (คงไว้และรายงานจำนวน)
- ระยะก่อนย่อหน้า 6 pt (`before=120`) เลือกด้วย `--doc`: `ราชการ` = ย่อหน้าเนื้อความของหนังสือ (หลัง "เรียน" ถึง "จึงเรียนมาเพื่อ…"
  ไม่รวมส่วนหัวหนังสือและส่วนลงชื่อ; บรรทัด อ้างถึง และ สิ่งที่ส่งมาด้วย (รวมรายการ "1. …" ใต้ข้อนั้น) ที่ต่อจาก "เรียน" ถือเป็นส่วนหัว ชิดใต้ "เรียน" ไม่ได้ 6 pt); `รายงาน` = หัวข้อทุกระดับ 6 pt เนื้อความ 0 pt (ไม่ทำกับตาราง); ย่อหน้าขึ้นต้นเลข ("1. …", "1.1 …") นับเป็นหัวข้อเมื่อตัวหนาทั้งย่อหน้าเท่านั้น (รายการเลขที่ไม่หนาเป็นเนื้อความ) จึงควรใช้สไตล์ Heading ของ Word หรือทำตัวหนาให้หัวข้อ
- "ตารางที่ n" ตัวหนาอยู่เหนือตาราง, "ภาพที่ n" อยู่ใต้ภาพ, หัวตาราง shading + `tblHeader` (ทำซ้ำแถวหัวตาราง)
- หัวตารางซ้ำไม่ขึ้นหน้าถัดไป: แถวที่ยาวเกินหน้าถูกตั้ง `cantSplit` ให้ปลดเฉพาะแถวยาว
  (ใน Word: Table Properties → Row → ติ๊ก Allow row to break across pages)
- ตารางซ้อนในแบบฟอร์มกรอบ: ความกว้างตารางใน (`tblW` + `gridCol` รวมกัน) ต้องน้อยกว่าความกว้าง cell กรอบนอก
- ผังแกนต์: เติมสีช่องด้วย `w:shd fill`, ไตรมาสเป็นเลขไทย ๑–๔, ใส่หมายเหตุเดือนของไตรมาสใต้ตาราง
- ช่องลงชื่อ: ตัดช่องว่างนำหน้าออก, `ind left≈3969` (7 ซม.) + `jc=center` + keepNext/keepLines ทั้งชุด
  (ย่อหน้าขึ้นต้น "(ลงชื่อ)", "(ตำแหน่ง)", "(วันที่)", "(นาย/นาง/นางสาว …)")

## 4. แก้ข้อความในไฟล์เดิมโดยไม่ทำรูปแบบเสีย

- **ดูโครงสร้างก่อนแก้**: ขนาดหน้าและขอบ (`pgSz`, `pgMar`), ตารางที่ตั้งหัวซ้ำ (`tblHeader`) และแถวห้ามแยก
  (`cantSplit`), การขึ้นบรรทัดด้วยมือ และฟอนต์ที่ใช้จริง (`check` รายงานรายชื่อฟอนต์ใน `MULTI_FONT`
  เมื่อมีมากกว่าหนึ่งชนิด) เพื่อรู้ว่าต้องคงอะไรไว้และเลือกตัวเลือกของ `fix` ให้ถูก
- **ค้นแบบ unique**: เทียบข้อความทั้งย่อหน้า (ต่อ `w:t` ทุกตัว) และยืนยันว่าพบ 1 ย่อหน้า ถ้าเจอซ้ำ
  (เช่น ในสารบัญหรือบทคัดย่อ) ให้จำกัดขอบเขตด้วยดัชนีบท หรือข้ามย่อหน้าที่สไตล์ขึ้นต้น `toc`
- **แก้ใน run เดียวก่อน** (รักษาตัวหนา/ลิงก์/hyperlink) ถ้าข้อความกระจายหลาย run ค่อยรวมเป็น run เดียว
  โดยใช้รูปแบบของ run แรก (ตัวหนาบางคำในย่อหน้าจะหาย บอกผู้ใช้)
- **ย่อหน้าที่มีเลขอ้างอิงยก (superscript)**: แปลงเป็น markup `ข้อความ{12,13}` → แทนข้อความ → สร้าง run ใหม่
  โดยคืน `vertAlign=superscript` ให้ส่วนใน `{}`
- **ตัวอักษรพิเศษ**: Word ใช้ `<w:noBreakHyphen/>` แทนขีดใน run (เช่น M.-P., Payne-Gagnon)
  ข้อความที่ดึงออกมาจึงไม่เห็นขีด อย่าเติมขีดซ้ำ
- ไฟล์ที่ตัดคำแล้ว (`check` รายงาน `WRAPPED`): รัน `unwrap` ก่อนแก้ แล้วค่อย `wrap` ใหม่
- หลังแก้ทุกครั้งรัน `fix` อีกรอบ

## 5. คัดลอกเนื้อหาข้ามไฟล์

1. คัดลอก element ลูกของ cell/body ต้นทาง (ข้าม `tcPr`) ด้วย `copy.deepcopy` แล้ววางต่อจาก anchor ในไฟล์ปลายทาง
2. ลบ `bookmarkStart/End` (กันชื่อชน) และ `w14:paraId/textId`
3. ภาพ: อ่าน `r:embed` → หาไฟล์ใน rels ต้นทาง → เพิ่มภาพเข้า part ปลายทาง + Relationship id ใหม่ →
   เปลี่ยน `r:embed`; ตั้ง `wp:docPr id` ใหม่ให้ไม่ซ้ำทั้งเอกสาร
4. สไตล์: ถ้า pStyle ชื่อเดียวกันแต่นิยามต่างกัน ให้คัดลอกนิยามจากต้นทางมาเป็นชื่อใหม่ (เช่น `F1Heading2`)
   แล้วชี้ pStyle ไปที่ชื่อใหม่
5. รัน `fix` หลังคัดลอก (docDefaults ของสองไฟล์มักต่างกัน `fix` ตั้งฟอนต์ทุก run ให้เท่ากัน)
6. ถ้าแม่แบบปลายทางมีลำดับหัวข้อต่างจากต้นทาง ให้ **จัดหัวข้อตามแม่แบบปลายทาง** แล้วบอกผู้ใช้ว่าเปลี่ยนเลขหัวข้ออะไรบ้าง

## 6. ตรวจก่อนส่งแบบละเอียด

1. `python "<โฟลเดอร์ skill>/scripts/thaidocx.py" check out.docx` ผ่าน (มีได้เฉพาะ `WRAPPED`) และเปิดด้วย python-docx ได้
2. แปลงเป็น PDF ดูด้วยตา (`preview.md`): ตารางล้น, หัวข้อค้าง, ช่องลงชื่อแยกหน้า, หัวตารางซ้ำ,
   ข้อความแตกบรรทัด, ตัวอักษรเพี้ยน (จำนวนหน้าจาก LibreOffice เป็นค่าประมาณ ใน Word อาจต่างเล็กน้อย)
3. นับหน้าที่มีคำสำคัญด้วย `pdftotext` (เช่น หัวตาราง "(ต่อ)" ขึ้นทุกหน้าหรือไม่)
4. ตรวจเนื้อหา: ตัวเลขในตาราง = ในข้อความ, การอ้างอิงในเนื้อหา ↔ รายการอ้างอิงครบทั้งสองทาง,
   เลข Vancouver เรียงตามการอ้างครั้งแรก, ตัวเลขตรงกันระหว่างเอกสารชุดเดียวกัน
5. บอกผู้ใช้: ไฟล์ใหม่ชื่ออะไร แก้อะไร คงอะไรไว้ ต้อง Update Field สารบัญใน Word และตรวจจุดตัดหน้าเอง
