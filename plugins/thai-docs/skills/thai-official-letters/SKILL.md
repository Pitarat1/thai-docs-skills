# หนังสือราชการ ๑๑ ชนิด (thai-official-letters)

## ใช้เมื่อไร

- ผู้ใช้ขอให้ร่าง/ทำหนังสือราชการ บันทึกข้อความ หนังสือส่งออก คำสั่งแต่งตั้ง ประกาศ หนังสือรับรอง รายงานการประชุม ฯลฯ
- ต้องการไฟล์ .docx ที่ระยะ ตำแหน่ง ขนาดอักษรตรงแนวทางการพิมพ์ ว ๒๐๑๙ ทุกครั้ง และเปิดแก้ต่อใน Word ได้
- ต้องการตรวจร่างหรือไฟล์ก่อนส่ง (วันที่ เลขที่ คำขึ้นต้น/คำลงท้าย ช่องที่ยังไม่ได้กรอก ขอบกระดาษ ฟอนต์)

## เตรียมเครื่อง

- Python 3.10 ขึ้นไป และไลบรารี: รันคำสั่ง `pip install python-docx lxml pydantic` (ทุกคำสั่งต้องใช้ pydantic)
- ถ้าจะตัดคำ (`--wrap-words`) ให้ติดตั้ง `numpy` เพิ่มเพื่อให้ตัดคำแม่นขึ้น ไม่มีก็ยังทำงานได้ (จะแสดงคำเตือนหนึ่งครั้ง ไม่ถือว่าล้มเหลว)
- รันคำสั่งในโฟลเดอร์งานของผู้ใช้ และเรียกสคริปต์ด้วย path เต็ม `<โฟลเดอร์ skill>` คือโฟลเดอร์ที่มีไฟล์ SKILL.md นี้
- ถ้าคำสั่งแจ้งว่าไม่พบไลบรารี ให้ติดตั้งตามข้อความที่แสดง แล้วรันใหม่

## ขั้นตอน

1. **เลือกชนิดหนังสือ** จากสิ่งที่ผู้ใช้ต้องการ (ตารางใน `references/doc-types.md` หรือรัน `types`) ถ้าไม่ชัดให้ถามผู้ใช้
2. **รวบรวมข้อเท็จจริงจากผู้ใช้** ห้ามแต่งชื่อ ตำแหน่ง เลขที่หนังสือ วันที่ ที่ผู้ใช้ไม่ได้ให้ ให้ใส่ `[ระบุ…]`
   เช่น `[ระบุวันที่]` `[ระบุตำแหน่ง]` (ช่องนี้เป็นแถบเหลืองในไฟล์ และตัวตรวจรายงานทุกจุด) รวมถึงตัวเลข
   งบประมาณ สถานที่ และชื่อหน่วยงานที่ผู้ใช้ไม่ได้บอก
3. **เขียนร่างเป็นไฟล์ JSON**: ดูโครงด้วย `schema ชนิด` หรือเริ่มจาก `example ชนิด ร่าง.json` แล้วแทนเนื้อหาทั้งหมด
   (ตัวอย่างใช้หน่วยงานและบุคคลสมมติ ห้ามปล่อยค่าตัวอย่างค้างไว้) เขียนเนื้อความตาม `references/writing.md`
   ใน JSON ใช้ `"doc_type"` เป็นรหัสภาษาอังกฤษ (`memo`, `external_letter` …) ส่วนคำสั่ง `schema`/`example` รับทั้งรหัสและชื่อไทย
4. **สร้างไฟล์และตรวจ**: `render` แล้ว `check` ไฟล์ร่าง แก้ร่างตามที่รายงาน แล้ว `render … --force` ใหม่
   จนไม่มีข้อผิดพลาด (เหลือได้เฉพาะ `PLACEHOLDER` ของช่องที่ผู้ใช้ต้องกรอกเอง)
5. **ดูผล**: แปลงเป็น PDF แล้วเปิดดูทุกหน้า (วิธีใน `references/preview.md`)
6. **สรุปให้ผู้ใช้**: ไฟล์ชื่ออะไร ช่อง `[ระบุ…]` ที่ยังต้องกรอก และบอกผู้ใช้ว่าต้องใส่ตราเอง ออกเลข และลงนามเอง
   (ถ้า `render` แจ้งว่าใช้กรอบแทนตรา ให้บอกวิธีระบุไฟล์ตราตาม `references/agency-profile.md` ชุดนี้ไม่แจกตรา)

หลัง `render` ถ้าต้องจัดหน้าไฟล์ .docx ต่อ (เช่น แก้ในไฟล์เดิมของผู้ใช้) ใช้ skill `thai-docx` ได้ถ้าติดตั้งไว้ ไม่บังคับ
ถ้าจะแก้เนื้อหา ให้แก้ร่าง JSON แล้ว `render` ใหม่ ดีกว่าแก้ในไฟล์ .docx

## ตัวอย่างครบหนึ่งรอบ

ผู้ใช้: "ทำบันทึกข้อความในนามกลุ่มงานตัวอย่าง กองตัวอย่าง โทร. 0 2000 0000 ถึง ผอ.กองตัวอย่าง
ขอใช้ห้องประชุมตัวอย่าง ชั้น 3 ประชุมคณะทำงานพัฒนาระบบเอกสาร 20 ธ.ค. 69 เวลา 9–12 น. 15 คน ผู้ลงนามนายสมมติ ตัวอย่าง"
— ไม่ได้ให้เลขที่หนังสือ วันที่ และตำแหน่งผู้ลงนาม จึงใส่ `[ระบุ…]` ไฟล์ `ร่าง.json`:

```json
{
  "doc_type": "memo",
  "department": "กลุ่มงานตัวอย่าง กองตัวอย่าง โทร. 0 2000 0000",
  "doc_no": "[ระบุ]/[ระบุ]",
  "date": "[ระบุวันที่]",
  "subject": "ขอใช้ห้องประชุม",
  "to": "ผู้อำนวยการกองตัวอย่าง",
  "body": {
    "cause": ["ด้วยกลุ่มงานตัวอย่างจะจัดประชุมคณะทำงานพัฒนาระบบเอกสาร ในวันที่ 20 ธันวาคม 2569 เวลา 09.00 - 12.00 น."],
    "purpose": ["ในการนี้ กลุ่มงานตัวอย่างขอใช้ห้องประชุมตัวอย่าง ชั้น 3 สำหรับผู้เข้าประชุม 15 คน"],
    "conclusion": "จึงเรียนมาเพื่อโปรดพิจารณาอนุมัติ"
  },
  "signer": {"name": "นายสมมติ ตัวอย่าง", "position": ["[ระบุตำแหน่ง]"]}
}
```

```bash
python "<โฟลเดอร์ skill>/scripts/thaigov.py" check ร่าง.json
python "<โฟลเดอร์ skill>/scripts/thaigov.py" render ร่าง.json บันทึก_ขอใช้ห้องประชุม.docx
python "<โฟลเดอร์ skill>/scripts/thaigov.py" check บันทึก_ขอใช้ห้องประชุม.docx
```

ผล: `check ร่าง.json` รายงาน "ข้อผิดพลาด 0 คำเตือน 3 ข้อสังเกต 0" คือ `PLACEHOLDER` ที่ `doc_no` `date`
`signer.position` (ผู้ใช้กรอกเอง) · `render` สร้างไฟล์ พิมพ์คำเตือนชุดเดียวกัน เปลี่ยนเลขเป็นเลขไทย
("โทร. ๐ ๒๐๐๐ ๐๐๐๐" "๒๐ ธันวาคม ๒๕๖๙ เวลา ๐๙.๐๐ – ๑๒.๐๐ น." "ชั้น ๓" "๑๕ คน") และแจ้งว่าใช้กรอบแทนตรา
· `check` ไฟล์ .docx รายงาน `PLACEHOLDER` ของ `[ระบุ]` `[ระบุวันที่]` `[ระบุตำแหน่ง]` ที่ยังเหลือในไฟล์ ไม่มีข้อผิดพลาด

## คำสั่ง

`python "<โฟลเดอร์ skill>/scripts/thaigov.py" <คำสั่ง> ...`

| คำสั่ง | ทำอะไร |
|---|---|
| `types` | รายการ ๑๑ ชนิด พร้อมรหัสและข้อของระเบียบ |
| `schema TYPE` | field ของชนิดนั้น (ชนิดข้อมูล จำเป็น/ค่าเริ่มต้น คำอธิบายพร้อมเลขข้อของระเบียบ) |
| `example TYPE [OUT.json]` | ร่างตัวอย่าง พิมพ์ทางจอเมื่อไม่ระบุ OUT; ไม่เขียนทับไฟล์ที่มีอยู่ |
| `render IN.json OUT.docx [ตัวเลือก]` | ตรวจโครง → เติมส่วนตายตัว → สร้าง .docx → พิมพ์สรุปผลตรวจ |
| `check IN.json [--profile FILE]` | ตรวจร่าง (เติมส่วนตายตัวและใช้ไฟล์ตั้งค่าแบบเดียวกับ `render` ผลจึงตรงกับไฟล์ที่จะได้) |
| `check IN.docx [--profile FILE] [--font NAME]` | ตรวจไฟล์: ขอบกระดาษ ฟอนต์ ขนาด ตรา หัวบันทึกข้อความ คุณภาพข้อความ และช่อง `[ระบุ…]` ที่ยังเหลือ (ครอบคลุมไฟล์ที่แก้ใน Word แล้ว) |

ตัวเลือก `--font NAME` ของ `check` มีความหมายเดียวกับของ `render`: ถ้า `render --font` ด้วยฟอนต์ที่ไม่ใช่ฟอนต์แห่งชาติ
ต้องใส่ `--font` ชื่อเดียวกันตอน `check` ด้วย มิฉะนั้นจะได้ข้อผิดพลาด `FONT` ทางที่ดีกว่าคือตั้งฟอนต์ที่ไฟล์ตั้งค่า
(`layout.font` ใน `references/agency-profile.md`) แล้วใช้ไฟล์ตั้งค่าเดียวกันทั้ง `render` และ `check`

ตัวเลือกของ `render`:

| ตัวเลือก | ความหมาย |
|---|---|
| `--emblem FILE` | ไฟล์ตรา PNG/JPEG (ลำดับการหาตราใน `references/agency-profile.md`) |
| `--profile FILE` | ไฟล์ตั้งค่าหน่วยงาน (ไม่ระบุ = `~/.thaidocs/agency.json` ถ้ามี) |
| `--font NAME` | ฟอนต์แทนค่าเริ่มต้น TH Sarabun New เช่น `--font "TH SarabunPSK"` |
| `--arabic-digits` | ไม่แปลงเลขเป็นเลขไทย (ค่าเริ่มต้นแปลงเลขอารบิกในร่างเป็นเลขไทย ยกเว้น URL อีเมล DOI และรหัสที่ขึ้นต้นด้วยอักษรละติน เช่น COVID-19, ISO 27001) |
| `--wrap-words` | ตัดคำไม่ให้ขาดกลางคำเป็นขั้นสุดท้าย (แก้เนื้อหาภายหลังให้แก้ร่างแล้ว `render` ใหม่) |
| `--words FILE` | ไฟล์คำเพิ่มเติม บรรทัดละคำ ใส่ได้หลายครั้ง ต้องใช้คู่กับ `--wrap-words` (หรือเก็บคำไว้ที่ `~/.thaidocs/words.txt`) |
| `--force` | เขียนทับไฟล์ปลายทางที่มีอยู่ (ไม่ใส่ = ปฏิเสธ) |

พฤติกรรมที่ควรรู้:

- `render` คืน exit code 0 เมื่อสร้างไฟล์ได้ **แม้ผลตรวจมีข้อผิดพลาด** ต้องอ่านบรรทัดสรุปเอง และพิมพ์เฉพาะข้อผิดพลาด/คำเตือน
  (ข้อสังเกตระดับ info ดูด้วย `check ร่าง.json`)
- `check` คืน exit code 1 เมื่อพบระดับ error เท่านั้น; ข้อผิดพลาดการใช้งานหรือร่างผิดโครงคืน 2 พร้อมข้อความไทยบอก field ที่ผิด
- การเติมส่วนตายตัว (ทำใน `render` และ `check IN.json`): เติมเฉพาะช่องที่ยังเป็นค่าเริ่มต้น ว่าง หรือ `[ระบุ…]`
  ไม่ทับค่าที่ร่างระบุ — ตัดคำ "เรื่อง"/"เรียน" ที่พิมพ์ซ้ำหน้าค่า ตัดวงเล็บรอบชื่อผู้ลงนาม เติมหน่วยงาน/โทร/ผู้ลงนามจากไฟล์ตั้งค่า
  ตั้งคำขึ้นต้น/คำลงท้ายของหนังสือภายนอกตามตำแหน่งผู้รับเมื่อร่างใช้ค่าเริ่มต้นทั้งคู่ ตัด "น." ท้ายเวลาเริ่ม/เลิกประชุม
  (ระบบต่อให้เอง) และเขียนข้อความส่งสำเนาของหนังสือประทับตราที่มี `forwarded` แต่ไม่มี `paragraphs`
- เลขที่หนังสือไม่ถูกเติมจากไฟล์ตั้งค่า ผู้ใช้ออกเลขเอง

## ผลตรวจ

ระดับ: `error` = ขัดกับระเบียบหรือ ว ๒๐๑๙ ทุกข้อมีที่อ้างในวงเล็บท้ายบรรทัด (เช่น "(ข้อ ๑๒.๓)" "(ว ๒๐๑๙)")
· `warning`/`info` = ข้อสังเกต บางข้อมีที่อ้าง บางข้อไม่มี ข้อที่เป็นธรรมเนียมการเขียนไม่มีที่อ้าง และข้อความลงท้ายว่า
"(ธรรมเนียมการเขียน ไม่ใช่ข้อกำหนดของระเบียบ)" อย่าบอกผู้ใช้ว่าข้อที่ไม่มีที่อ้าง "ผิดระเบียบ"
ความหมายและวิธีแก้ของทุกรหัสอยู่ใน `references/doc-types.md`

## ตรวจก่อนส่ง

- [ ] `check ร่าง.json` ไม่มีข้อผิดพลาด และ `check ไฟล์.docx` ไม่มีข้อผิดพลาด
- [ ] ไม่มีชื่อ ตำแหน่ง เลขที่ วันที่ ที่แต่งขึ้นเอง ทุกจุดที่ผู้ใช้ไม่ได้ให้เป็น `[ระบุ…]`
- [ ] ไม่มีค่าจากไฟล์ตัวอย่าง (กรมตัวอย่าง นายสมมติ ตัวอย่าง) ค้างในร่าง เว้นแต่ผู้ใช้ให้มาเอง
- [ ] แปลง PDF ดูทุกหน้าแล้ว: ช่องลงชื่อไม่แยกหน้า เลขหน้า "- ๒ -" ตั้งแต่หน้าที่สอง ตราอยู่ถูกที่
- [ ] คำขึ้นต้น/คำลงท้ายตรงฐานะผู้รับ (`references/writing.md`)
- [ ] สรุปให้ผู้ใช้: ชื่อไฟล์ ช่องที่ยังต้องกรอก และสิ่งที่ต้องทำเอง (ใส่ตรา ออกเลข ลงวันที่ ลงนาม)

## อ่านเพิ่ม (เปิดไฟล์เมื่อจำเป็น)

- `references/doc-types.md` — ใช้ชนิดไหนเมื่อไร ข้อของระเบียบ กระดาษ/ตรา ผู้ลงนาม ตารางรหัสผลตรวจ
- `references/writing.md` — โครง ๓ ภาค คำเปิด คำลงท้ายภาคสรุป การเขียน "เรื่อง" คำขึ้นต้น/คำลงท้าย
- `references/layout-w2019.md` — ค่าการพิมพ์ทุกค่าและที่มา ฟอนต์
- `references/agency-profile.md` — ไฟล์ตั้งค่าหน่วยงาน (`agency.json`) และลำดับการหาไฟล์ตรา
- `references/preview.md` — แปลง docx เป็น PDF เพื่อดูผล
