## ผลทดลองที่ใช้ออกแบบ (11 พ.ย. 2569, Word for Mac)

ข้อความทดสอบ 4 ย่อหน้า (หนังสือราชการ ผลการศึกษายา ไซเบอร์ งานวิจัย) × ความกว้าง 7 ขนาด ≈ 200 จุดขึ้นบรรทัด เทียบกับขอบเขตคำที่กำหนดด้วยมือ

| วิธีใน Word | ตัดกลางคำ |
|---|---|
| ปล่อย Word ตัดเอง (run ติดป้ายไทยตามปกติ) | 12.8% |
| + ZWSP ระหว่างคำ | 12.8% (Word ไม่สนใจ) |
| + Word Joiner ในคำ | 93% (Word เลิกใช้พจนานุกรมไทย ตัดได้ทุกที่) |
| **แยกคำละ run ไม่ติดป้ายไทย + ZWSP ระหว่างคำ** | **2.0%** |

| ตัวตัดคำ | ตัดกลางคำ |
|---|---|
| newmm พจนานุกรม PyThaiNLP | 10.5% |
| + พจนานุกรมเสริม (ชื่อคน จังหวัด อำเภอ คำเฉพาะ) | 5.4% |
| + พจนานุกรมเสริม ∩ khammoon | 2.2% |

- newmm ไม่เคยรายงานคำที่ไม่รู้จัก มันซอยชื่อเฉพาะเป็นคำที่รู้จัก (`เมท|ฟอร์|มิน`) จึง **ใช้จุดตัดที่ทั้งสองตัวเห็นตรงกัน (intersection)** แทน "ส่ง OOV ให้ khammoon"
- khammoon ช่วยคำทับศัพท์ (ชื่อยา ศัพท์เทคโนโลยี) ที่ใส่พจนานุกรมให้ครบไม่ได้; ชื่ออำเภอ/ระบบ แก้ด้วยพจนานุกรมเสริม
- กระจายแบบไทยยังทำงานใน run ที่ไม่ติดป้ายไทย (ดูภาพหน้ากระดาษแล้ว)

## skill `thai-docx`

**ใช้เมื่อ:** สร้างหรือแก้ไฟล์ Word ภาษาไทย (รายงาน แบบฟอร์ม หนังสือ เอกสารประกอบ) ให้ฟอนต์ ขนาด การตัดบรรทัด กระจายแบบไทย และการพิมพ์ถูกต้อง

`SKILL.md` สั้น (≈150 บรรทัด): เมื่อไรใช้, ขั้นตอนทำงาน, คำสั่ง CLI, ตรวจก่อนส่ง แล้วชี้ไป `references/` สำหรับรายละเอียด เขียนเป็นขั้นตอนทั่วไป ("รันคำสั่ง…", "เปิดไฟล์…") ไม่อ้างเครื่องมือเฉพาะของ AI ตัวใด

### คำสั่ง (`python scripts/thaidocx.py …`)

| คำสั่ง | ทำอะไร |
|---|---|
| `fix IN OUT [ตัวเลือก]` | post-process ทั้งไฟล์ตามหลัก 10 ข้อ (ลำดับด้านล่าง) |
| `check IN` | รายงานปัญหาโดยไม่แก้: run ไทยไม่มี `cs`/lang, `sz≠szCs`, theme font, ฟอนต์หลายแบบ, ขึ้นบรรทัดด้วยมือ, อักษรเพี้ยน (U+F70x, ํา), เลขอารบิก/ไทยปนกัน (ถ้าระบุ `--thai-digits`), สถานะ wrap-words; exit code ≠ 0 ถ้าพบปัญหา |
| `wrap IN OUT [--words FILE]` | ตัดคำไม่ให้ขาดกลางคำ (หัวข้อถัดไป) |
| `unwrap IN OUT` | ถอด wrap กลับเป็น run ไทยปกติ (ก่อนแก้เนื้อหาต่อ) |
| `segment "ข้อความ" [--words FILE]` | พิมพ์ผลตัดคำ `คำ|คำ|…` ไว้ตรวจ/เพิ่มคำเอง |

ตัวเลือกของ `fix`: `--font "TH Sarabun New"` (ค่าเริ่มต้น), `--body-pt 16`, `--thai-digits`, `--distribute` (ตั้ง thaiDistribute ให้ย่อหน้าเนื้อความ), `--remove-manual-breaks`, `--wrap-words` (เรียก wrap เป็นขั้นสุดท้าย), `--words FILE`

ลำดับใน `fix`: normalize อักษร → ฟอนต์ทั้งเอกสาร (ลบ theme) → `sz=szCs`, `b`+`bCs` → (เลือก) ลบ br มือ → (เลือก) เลขไทย → (เลือก) thaiDistribute → keepNext หัวข้อ → `thai_runs` + ซ่อนเส้นตรวจคำ + ค่าเริ่มต้นย่อหน้า → (เลือก) wrap ทำสุดท้ายเพราะขั้นอื่นสร้าง run ใหม่

ใช้เป็นไลบรารีได้ด้วย: `from thaidocs import layout, wrap` → `layout.finalize(doc, font=…)` สำหรับเอกสารที่ AI สร้างใหม่ด้วย python-docx (SKILL.md มีตัวอย่างสั้นๆ)

ไม่แก้ไฟล์ต้นฉบับทับ: OUT ต้องเป็นคนละไฟล์กับ IN (ปฏิเสธถ้าเหมือนกัน)

### ที่มาของโค้ด

- `layout`: รวม `engine/sarabun/render/thai_layout.py` (ใช้จริงในระบบ) กับฟังก์ชันใน skill `thai-docx-layout-th` (normalize อักษร, เลขไทย, br มือ, keepNext, หัวตารางซ้ำ) เขียนใหม่บน python-docx + lxml
- เลขไทย: ตามกติกาข้อ 3 ของ skill เดิม (แปลงเฉพาะ `w:t` ไม่แตะ `instrText`, คง URL/DOI/อักษรละตินติดตัวเลข, `numFmt thaiNumbers`, `pgNumType`)

## การตัดคำ (`thaidocs.wordcut` + `thaidocs.wrap`)

### ตัวตัดคำ

`boundaries(text) -> set[int]` = จุดตัดของ newmm (พจนานุกรมรวม) ∩ จุดตัดของ khammoon (ถ้ามี) — ช่องว่างและการเปลี่ยนระหว่างไทย/ไม่ใช่ไทยเป็นจุดตัดเสมอ

- **newmm + TCC**: คัดลอกจาก PyThaiNLP (Apache-2.0, ~400 บรรทัด) ไม่ลง PyThaiNLP ทั้งก้อน (66 MB)
- **พจนานุกรมรวม** ใน `data/`:
  - `words_th.txt` ของ PyThaiNLP (~62,000 คำ, 1.5 MB)
  - ชื่อคน/นามสกุล/จังหวัด ของ PyThaiNLP
  - `places_th.txt`: ชื่ออำเภอ/ตำบลทั่วประเทศ จากข้อมูลเปิดของกรมการปกครอง (ตรวจสัญญาอนุญาตตอนลงมือ ถ้าใช้ไม่ได้ให้เหลือเฉพาะจังหวัด+อำเภอที่รวบรวมเอง)
  - `domain_th.txt`: คำเฉพาะทางที่พบบ่อยในงานราชการ/สาธารณสุข/ไซเบอร์ (ตำแหน่ง ระดับ ชื่อระบบ) เริ่มจากรายการเล็กที่คัดเอง
  - `--words FILE` ของผู้ใช้ (บรรทัดละคำ) และ `~/.thaidocs/words.txt` ถ้ามี
- **khammoon (ส่วนเสริม)**: คัดลอกเฉพาะ backend numpy + `weights.npz` (~4 MB) ไว้ใน `scripts/thaidocs/_khammoon/` ถ้า import ไม่ได้ (ไม่มี numpy หรือถูกถอดออก) ใช้ newmm อย่างเดียวและพิมพ์เตือนครั้งเดียวว่า "คำทับศัพท์อาจขาดกลางคำ" ถอดออกได้ด้วย `tools/build.py --without-khammoon`

### wrap ใน Word

ต่อย่อหน้าที่มีอักษรไทย:

1. ลบ ZWSP เดิมทั้งหมด (ทำซ้ำได้ผลเท่าเดิม)
2. ต่อข้อความทุก run เพื่อหาจุดตัดทั้งย่อหน้า (คำอาจคร่อมหลาย run)
3. แยก run ที่จุดตัดคำ คัดลอก `rPr` เดิม (ตัวหนา ขีดเส้นใต้ ยกกำลัง คงอยู่)
4. run ที่มีอักษรไทย: ลบ `w:cs`, ตั้ง `w:lang w:val="en-US" w:bidi="en-US"`, ตั้ง `rFonts` ascii/hAnsi/cs เป็นฟอนต์เดียวกัน, `sz=szCs`
5. ใส่ ZWSP (U+200B) ระหว่างคำไทยที่ติดกัน
6. บันทึกเครื่องหมายใน custom property ของไฟล์ (`thaidocs.wrapped=1`) เพื่อให้ `check`/`unwrap` รู้

ข้าม: field code (`instrText`), ช่องกาเครื่องหมาย/สัญลักษณ์, run ที่ไม่มีอักษรไทย, ย่อหน้าที่ไม่มีไทย

`unwrap`: ลบ ZWSP, คืน `w:cs` + `w:lang bidi=th-TH` ให้ run ไทย, รวม run ติดกันที่ `rPr` เหมือนกัน, ลบ property

### ข้อแลกเปลี่ยน (เขียนใน `references/wrap-words.md` และ README)

- เป็นขั้น **สุดท้ายก่อนส่ง/พิมพ์** ข้อความที่พิมพ์เพิ่มภายหลังจะไม่ได้ป้ายไทย → `unwrap` ก่อนแก้ แล้ว `wrap` ใหม่
- เส้นตรวจคำสะกดต้องซ่อน (ทำอยู่แล้วใน `fix`)
- ค้นหาคำเดียวใน Word เจอ แต่ค้นวลีที่ข้ามคำอาจไม่เจอเพราะมี ZWSP; คัดลอกข้อความออกไปจะติด ZWSP ไปด้วย
- ไม่ใช่ค่าเริ่มต้นของ `fix` — ต้องสั่ง `--wrap-words` หรือ `wrap`
- ตรวจแล้วเฉพาะ Word for Mac; Word for Windows และ LibreOffice ต้องตรวจก่อนประกาศว่ารองรับ (หัวข้อทดสอบ)

## ทดสอบ

- **ตัวตัดคำ**: ชุดทดสอบจากการทดลอง (4 ย่อหน้า ขอบเขตคำกำหนดด้วยมือ) + ขยายเพิ่มด้วยข้อความหนังสือราชการ/รายงานวิจัย ≥ 10 ย่อหน้า เกณฑ์: ตัดกลางคำ ≤ 3% เมื่อมี khammoon, ≤ 6% เมื่อไม่มี; ผลไม่เปลี่ยนข้อความ (`''.join(words) == text`)
- **layout**: ทุก run ไทยมี `cs`+`lang bidi`, `sz==szCs`, ไม่มี theme font, ลำดับ element ตาม schema, เลขไทยไม่แตะ `instrText`/URL
- **wrap/unwrap**: ข้อความหลัง unwrap เท่ากับก่อน wrap; wrap ซ้ำได้ผลเดิม; ตัวหนา/ยกกำลังคงอยู่; ไฟล์เปิดด้วย python-docx ได้และผ่าน `validate.py` ของ docx skill
- **Word for Mac** (สคริปต์สำหรับผู้พัฒนา `tools/word_breaks.py`): สร้างไฟล์ทดสอบ → Word แปลง PDF → นับการตัดกลางคำ เกณฑ์ ≤ 3%
- **Word for Windows / LibreOffice**: ส่งไฟล์ทดสอบให้คนในทีมเปิดและดูจุดขึ้นบรรทัด (บันทึกผลใน README ส่วน "ทดสอบกับ")
- **ข้ามแพลตฟอร์ม**: ลองใช้ skill จริงใน Claude Code และอย่างน้อยหนึ่งใน Codex/Antigravity ถ้ามีในเครื่อง ตัวที่ไม่ได้ลองระบุว่า "ยังไม่ได้ทดสอบ"
- CI: GitHub Actions รัน pytest ทุก push และก่อนสร้าง release zip
