# ชุด skill เอกสารไทย — โครงการย่อยที่ 2: หนังสือราชการ 11 ชนิด

วันที่ 14 พ.ย. 2569 · สถานะ: ผู้ใช้อนุมัติแล้ว (14 พ.ย. 2569) · ต่อจาก `2026-11-11-thai-docs-skills-core-design.md`

## เจตนา

แจกความรู้ "ทำหนังสือราชการให้ถูกแบบ" ที่ใช้งานจริงอยู่ในระบบต้นทาง (แกน `engine/sarabun` ซึ่งมาจาก SARABUN.AI ของ กปภ. Apache-2.0) ให้คนทั่วไปใช้ผ่าน AI ตัวใดก็ได้ ผู้ใช้บอกเรื่องที่ต้องการ AI เขียนเนื้อหา สคริปต์จัดรูปแบบเป็นไฟล์ Word ที่ระยะ ตำแหน่ง ขนาดอักษรตรงตามระเบียบสำนักนายกรัฐมนตรีว่าด้วยงานสารบรรณ พ.ศ. 2526 (และที่แก้ไขเพิ่มเติม) และแนวทางการพิมพ์ นร 0106/ว 2019 ทุกครั้ง

## เป้าหมาย

- skill ใหม่ `thai-official-letters` สร้างหนังสือราชการได้ครบ 11 ชนิด: บันทึกข้อความ หนังสือภายนอก หนังสือประทับตรา คำสั่ง ระเบียบ ข้อบังคับ ประกาศ แถลงการณ์ ข่าว หนังสือรับรอง รายงานการประชุม
- ผลลัพธ์เป็น .docx ที่เปิดแก้ต่อใน Word ได้ และผ่าน `check` ของ `thai-docx`
- ตรวจเนื้อหาและรูปแบบได้ก่อนส่ง (วันที่ เลขที่ คำขึ้นต้น/คำลงท้าย ส่วนที่ยังไม่ได้กรอก ขอบกระดาษ ฟอนต์)
- ใช้ได้กับ Claude Code, claude.ai, Codex, Antigravity แบบเดียวกับโครงการ 1

## ไม่ทำ

- ไม่เรียก AI ภายนอกจากสคริปต์ (ไม่นำ `llm/`, `service.py` มา)
- ไม่นำการถอดเสียงประชุม (`minutes.py`) ชุดแบบฟอร์มการเงิน/เดินทาง/ล่วงเวลา/ประชุม (`packages/`) และโปรไฟล์หน่วยงาน 2 ชุดของต้นทางมา
- ไม่แจกตราครุฑหรือตราหน่วยงานใด
- ไม่ทำตารางคำขึ้นต้น/คำลงท้ายครบทั้งภาคผนวก 2 (พระราชวงศ์ พระภิกษุ) ใช้ชุดที่พบบ่อยของต้นทาง
- ไม่ทำระบบออกเลขหนังสือ ลงนามอิเล็กทรอนิกส์ หรือส่งหนังสือ

## สิ่งที่ถือว่าล้มเหลวแม้โค้ดทำงาน

- สคริปต์หรือเอกสาร skill ทำให้ AI แต่งชื่อคน ตำแหน่ง เลขที่หนังสือ หรือวันที่ที่ผู้ใช้ไม่ได้ให้มา
- มีชื่อหน่วยงานจริง ชื่อบุคคลจริง ข้อมูลภายใน หรือ path ในเครื่องผู้พัฒนาหลุดเข้า repo สาธารณะ (รวมในตัวอย่างและชุดทดสอบ)
- skill `thai-docx` เดิมทำงานต่างไปจาก v0.1.0

## ข้อจำกัด

- ผู้ใช้ตกลงไว้ในโครงการ 1: สคริปต์ Python เรียกจากบรรทัดคำสั่ง เนื้อหา skill ไม่ผูกเครื่องมือของ AI ตัวใด ฟอนต์เริ่มต้น TH Sarabun New และหนังสือราชการใช้เลขไทย
- แก้โค้ดที่ `src/thaidocs/` ที่เดียว สำเนาในโฟลเดอร์ skill มาจาก `tools/build.py`
- แต่ละ skill ต้องอยู่ได้ด้วยตัวเองเมื่อ zip (claude.ai)
- ห้ามแก้ไฟล์ในโปรเจกต์ต้นทาง อ่านอย่างเดียว
- งานอยู่บน branch `feat/official-letters` ที่แตกจาก `public-main` การ push / release / เผยแพร่ ต้องให้ผู้ใช้อนุมัติแต่ละครั้ง

## สิ่งที่นำมาจากต้นทาง และสิ่งที่เปลี่ยน

แพ็กเกจย่อยใหม่ `src/thaidocs/official/`:

|---|---|---|
| `schema.py` | `schema.py` | คงโครงข้อมูล 9 แบบที่ครอบ 11 ชนิด (ระเบียบ/ข้อบังคับ และ แถลงการณ์/ข่าว ใช้แบบร่วม) ลบข้อความอ้างหน่วยงานเฉพาะในคำอธิบาย field |
| `style.py` | `style.py` | คง `LayoutSpec` และค่าที่มีที่มา [ว2019]/[ระเบียบ]/[แผ่นแบบ] เปลี่ยนฟอนต์เริ่มต้นเป็น TH Sarabun New ไม่มีโปรไฟล์หน่วยงานติดมา |

| `fill.py` | ส่วน `_postprocess` และ `forward_paragraphs` ใน `service.py` | เติมส่วนที่ไม่ต้องให้ AI ตัดสิน: ตัดคำว่า "เรื่อง"/"เรียน" ที่พิมพ์ซ้ำ เติมที่อยู่/โทร/ผู้ลงนามจากไฟล์ตั้งค่าหน่วยงาน ข้อความหนังสือประทับตราส่งสำเนา **ต่างจากต้นทาง: เติมเฉพาะ field ที่ยังเป็นค่าเริ่มต้นหรือ `[ระบุ…]` ไม่ทับค่าที่ร่างระบุมา** คำขึ้นต้น/คำลงท้ายที่ร่างระบุเองจึงคงอยู่ (เช่น ผู้รับเป็นพระภิกษุ) และตัวตรวจเตือนเมื่อไม่เข้าคู่กับตารางที่มี |

- ข้อความ `[ระบุ…]` แสดงเป็นแถบเหลืองในไฟล์ และตัวตรวจรายงานทุกจุดที่ยังไม่ได้กรอก
- ระยะใช้แบบ "ก่อนย่อหน้า" ตาม ว 2019 (6 pt ระหว่างภาค 12 pt ก่อนคำลงท้าย) ไม่ใส่บรรทัดว่าง ยกเว้นช่วงลงลายมือชื่อ
- เลขหน้า "- ๒ -" กึ่งกลางบน ตั้งแต่หน้าที่สอง
- ชั้นความเร็ว/ชั้นความลับ ตามระเบียบข้อ 28

```
plugins/thai-docs/skills/thai-official-letters/
  SKILL.md
  references/
    doc-types.md        ใช้ชนิดไหนเมื่อไร + field ของแต่ละชนิด
    writing.md          หลักการเขียน: ภาคเหตุ/ความประสงค์/สรุป ถ้อยคำ คำขึ้นต้น/คำลงท้าย
    layout-w2019.md     ค่าการพิมพ์และที่มาของแต่ละค่า
    agency-profile.md   ไฟล์ตั้งค่าหน่วยงานและตรา
    preview.md          (เหมือนของ thai-docx)
  scripts/thaigov.py    CLI จุดเดียว
  scripts/thaidocs/     สำเนาแพ็กเกจจาก src/ (รวม official/ และร่าง JSON ตัวอย่างชนิดละ 1 ไฟล์
                        ใน official/examples/ หน่วยงานและบุคคลสมมติ เรียกดูด้วยคำสั่ง example)
```

### ขั้นตอนที่ SKILL.md สอน AI

1. เลือกชนิดหนังสือจากสิ่งที่ผู้ใช้ต้องการ (ตารางใน `doc-types.md`) ถ้าไม่ชัดให้ถามผู้ใช้
2. รวบรวมข้อเท็จจริงจากผู้ใช้ สิ่งที่ไม่รู้ให้ใส่ `[ระบุ…]` **ห้ามแต่งชื่อ ตำแหน่ง เลขที่ วันที่**
3. เขียนร่างเป็นไฟล์ JSON (ดูโครงด้วยคำสั่ง `schema` หรือเริ่มจาก `example`)
4. รัน `render` แล้ว `check` แก้ตามที่รายงาน
5. แปลง PDF ดูทุกหน้า
6. สรุปให้ผู้ใช้: ไฟล์ชื่ออะไร จุดที่ยังต้องกรอก และสิ่งที่ต้องทำเอง (ใส่ตรา ออกเลข ลงนาม)

### คำสั่ง (`python "<โฟลเดอร์ skill>/scripts/thaigov.py" …`)

| คำสั่ง | ทำอะไร |
|---|---|
| `types` | รายการ 11 ชนิด พร้อมรหัสและข้อของระเบียบ |
| `schema TYPE` | โครง field ของชนิดนั้น (ชื่อ ชนิดข้อมูล คำอธิบายไทย ค่าเริ่มต้น) |
| `example TYPE [OUT.json]` | ร่างตัวอย่างของชนิดนั้น |
| `render IN.json OUT.docx [ตัวเลือก]` | ตรวจโครง → เติมส่วนตายตัว → สร้าง .docx → พิมพ์สรุปผลตรวจ |
| `check IN.json` หรือ `check IN.docx` | ตรวจร่างหรือตรวจไฟล์ ไม่แก้ไฟล์ คืน exit code 1 เมื่อมีระดับ error |

ตัวเลือกของ `render`: `--emblem FILE.png`, `--profile FILE.json`, `--font`, `--arabic-digits` (ปิดเลขไทย), `--wrap-words` และ `--words FILE` (ตัดคำด้วยแกนเดิมเป็นขั้นสุดท้าย)

`check IN.json` เติมส่วนตายตัวและรับ `--profile` แบบเดียวกับ `render` ก่อนตรวจ ผลจึงตรงกับไฟล์ที่จะได้

`OUT` ต้องไม่ทับไฟล์ที่มีอยู่ เว้นแต่ใส่ `--force` JSON ที่โครงผิดให้รายงานเป็นภาษาไทยว่า field ใดผิดอย่างไร แล้วคืน exit code 2

### ตราและไฟล์ตั้งค่าหน่วยงาน

- ตรา: `--emblem` > `emblem_png` ในไฟล์ตั้งค่า > `~/.thaidocs/emblem.png` > กรอบสี่เหลี่ยมแทนตรา เมื่อใช้กรอบแทน `render` พิมพ์บอกหนึ่งบรรทัด และ SKILL.md ให้ AI บอกผู้ใช้ว่าต้องใส่ตราเอง
- กรอบแทนตราเป็นไฟล์ PNG เล็กที่แจกมาใน `data/` (ไม่ต้องพึ่ง Pillow)
- ไฟล์ตั้งค่า (`--profile` หรือ `~/.thaidocs/agency.json`) มีสองส่วน: `agency` (ชื่อหน่วยงาน ที่อยู่ ส่วนราชการเจ้าของเรื่อง โทร อีเมล รหัสเลขที่หนังสือ ผู้ลงนามปกติ) ใช้เติมแทน `[ระบุ…]` และ `layout` (ค่าใน `LayoutSpec` ที่ต้องการเปลี่ยน เช่น ฟอนต์ ขอบกระดาษ คำว่า "หน่วยงาน" แทน "ส่วนราชการ" ชนิดที่ไม่พิมพ์ผู้ลงนาม) key ที่ไม่รู้จักให้แจ้งผิดพลาด

## ทดสอบ

- **โครงข้อมูล**: ตัวอย่างทั้ง 11 ชนิดผ่านการตรวจโครง JSON ที่ผิดได้ข้อความไทยชี้ field
- **ตัวสร้าง**: ทั้ง 11 ชนิดสร้างได้ เปิดด้วย python-docx ได้ ผ่าน `check` ของ `thai-docx` และวัดค่าจากไฟล์ตรง `LayoutSpec` (A4 ขอบซ้าย 3 ขวา 2 ซม. "บันทึกข้อความ" ตัวหนา 29 pt ป้ายหัวบันทึก 20 pt ย่อหน้า 2.5 ซม. ก่อนย่อหน้า 6 pt ก่อนคำลงท้าย 12 pt เว้น 3 บรรทัดก่อนชื่อผู้ลงนาม)
- **เลข**: ใช้กติกาเดียวกับแกน (`thaidocs.digits`): ค่าเริ่มต้นไม่เหลือเลขอารบิก ยกเว้นที่แกนคงไว้ (URL อีเมล DOI รหัสที่ขึ้นต้นด้วยอักษรละติน เช่น COVID-19, ISO 27001) `--arabic-digits` ปิดการแปลง: เลขอารบิกในร่างคงเป็นเลขอารบิก ส่วนเลขที่พิมพ์เป็นเลขไทยในร่างคงเป็นเลขไทย
- **ตัวตรวจ**: กติกาแต่ละข้อมีกรณีผ่านและไม่ผ่าน
- **ตรา**: ลำดับการเลือกไฟล์ตรา และกรณีใช้กรอบแทน
- **build**: `--check` ผ่านทุก skill เนื้อหา `thai-docx` ไม่มี `official/` zip ของ skill ใหม่แตกแล้วรัน `render` ได้โดยไม่มี `src/`
- **ความสะอาด**: เทสใน repo ค้นเฉพาะรูปแบบทั่วไป (path โฟลเดอร์ผู้ใช้ในเครื่อง ที่อยู่อีเมลที่ไม่ใช่ตัวอย่าง) ในไฟล์ที่ git ติดตาม รายชื่อหน่วยงาน/บุคคลจริงของต้นทางไม่ใส่ในเทส (การใส่คือการเปิดเผยเอง) ให้ผู้พัฒนาค้นด้วยมือก่อน push จากรายการที่เก็บในไฟล์นอก git ชื่อ กปภ. ใน `NOTICE`/`README.md` คงไว้เพราะเป็นการระบุที่มาตามสัญญาอนุญาต และชื่อจังหวัดใช้เป็นตัวอย่างได้
- **ด้วยตา (ผู้พัฒนา)**: หนังสือภายนอก บันทึกข้อความ ประทับตรา คำสั่ง แปลง PDF ด้วย Word for Mac ทีละไฟล์ เทียบกับตัวอย่างแนบ ว 2019 แล้วลบไฟล์ทดสอบ
- เทสเดิมของโครงการ 1 ผ่านทั้งหมด

## สิ่งที่ผู้เขียน spec ตัดสินใจเอง (ผู้ใช้ตรวจได้)

1. ชื่อ skill `thai-official-letters` และสคริปต์ `thaigov.py`
2. คงฟอนต์เริ่มต้น TH Sarabun New (ว 2019 ระบุ TH SarabunPSK) ตัวตรวจยอมรับฟอนต์แห่งชาติทุกตัว
3. โค้ดอยู่ในแพ็กเกจย่อย `thaidocs.official` และ skill ใหม่มีสำเนา `thaidocs` ทั้งชุดรวมตัวตัดคำ (repo ใหญ่ขึ้นราว 6 MB จากพจนานุกรมและโมเดลที่ซ้ำ)
4. pydantic เป็นไลบรารีบังคับของ skill ใหม่เท่านั้น
5. คงความสามารถ "หนังสือประทับตราส่งสำเนาหนังสือเพื่อทราบ" เป็นของทั่วไป ไม่ระบุว่าเป็นแนวปฏิบัติของหน่วยงานใด
6. คงค่าปรับแต่งใน `LayoutSpec` ที่ตัวสร้างรองรับอยู่ แต่ทดสอบและเขียนเอกสารเฉพาะชุดที่ระบุในหัวข้อไฟล์ตั้งค่า
7. `references/writing.md` เขียนใหม่จากระเบียบงานสารบรรณและกติกาที่ตัวตรวจใช้อยู่ (ภาคเหตุ/ความประสงค์/สรุป คำเปิด คำลงท้าย ถ้อยคำ) **ไม่คัดหรือเรียบเรียงจากคู่มือการเขียนของต้นทาง** เพราะคู่มือนั้นเป็นฉบับใช้งานของหน่วยงานหนึ่ง สรุปจากหนังสือของผู้อื่น และไม่พบไฟล์สัญญาอนุญาตของเอกสาร `NOTICE` จึงไม่ต้องอ้าง CC BY
8. ของที่เป็นแนวปฏิบัติหน่วยงานแต่ใช้ได้ทั่วไป คงไว้แบบไม่อ้างหน่วยงาน: บันทึกเสนอเรื่องแบบมีหัวข้อ (เรื่องเดิม ข้อเท็จจริง ข้อกฎหมาย ข้อพิจารณา ข้อเสนอ) โดยคำเตือน "ควรจบด้วยข้อเสนอ" เป็นระดับ info; คำแนะนำภาคสรุปของหนังสือประทับตราเป็นระดับ info ไม่อ้างแนวปฏิบัติ; ตัวเลือก "หนังสือประทับตราใช้แจ้งเพื่อทราบเท่านั้น" ปิดเป็นค่าเริ่มต้น เปิดได้ในไฟล์ตั้งค่า
9. ผลตรวจที่อ้าง "ตามระเบียบ" ต้องมีเลขข้อของระเบียบหรือ ว 2019 กำกับ ข้อที่เป็นธรรมเนียมให้เป็นระดับ info หรือ warning เท่านั้น
10. ค่าเริ่มต้นวันใช้บังคับของคำสั่งเป็น `[ระบุวันใช้บังคับ]` ไม่ใช่ 'บัดนี้'

## ปล่อยให้ผู้ลงมือทำตัดสิน

- รูปแบบผลลัพธ์ของ `schema TYPE` (ข้อความอ่านง่ายหรือ JSON Schema)
- การแบ่งไฟล์ภายใน `official/` และชื่อฟังก์ชัน
- ค่าปรับแต่งใน `LayoutSpec` ที่ไม่มีเทสครอบ จะคงหรือตัด (ถ้าตัดต้องไม่กระทบค่าเริ่มต้น)
- การวัดความกว้างข้อความด้วยไฟล์ฟอนต์ (fontTools) คงเป็นส่วนเสริมที่ไม่บังคับ หรือใช้ค่าประมาณอย่างเดียว

## ต้องยืนยันระหว่างลงมือ

- `layout.finalize` ของแกน (บังคับบรรทัดเดี่ยว ยกเว้นระยะ exact) ไม่ทำให้ระยะของตัวสร้างเพี้ยน ถ้าเพี้ยนให้แก้ที่ฝั่ง `official/` ไม่แก้พฤติกรรมของ `thai-docx`
- ขนาด zip ของ skill ใหม่ไม่เกินที่ claude.ai รับ
